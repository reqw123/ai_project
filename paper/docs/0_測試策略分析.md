## 分類判斷標準

| 分類 | 判斷標準 |
|---|---|
| **Pure Function** | 給定相同輸入，永遠回傳相同輸出；不讀寫外部狀態（檔案/網路/環境變數/`self`/全域變數/系統時鐘）、不修改傳入的可變參數 |
| **副作用 (IO)** | 檔案讀寫、網路請求（HTTP/MQTT）、`print`、`os.environ`/環境變數讀取、`datetime.now()`/`time.time()`（系統時鐘也算一種外部狀態）、修改傳入的可變物件（例如就地繪製到 `frame` numpy array） |
| **依賴 GPU** | 直接呼叫 `torch`/`ultralytics` 進行張量運算或模型推論，或查詢 `torch.cuda.is_available()` |
| **依賴 Flask** | 直接使用 `flask.Response`/`flask.request`/`@app.route` 等 Flask API |
| **依賴 Node-RED** | 直接組裝送往 Node-RED 端點的 payload，或直接對 Node-RED URL 發送 HTTP/MQTT |

有些函式會同時符合多個分類（例如 Flask route handler 內部也做了 IO）；表格中會列出全部符合的分類。

## 綜合結論

### Q1-5 快速索引（跨模組彙整）

- **Pure Function 最集中的模組**：`models/stgcn_model.py`（前處理管線 9 個函式）、`processors/skeleton_quality_assessment.py`（全部 7 個函式）、`analytics/*`（已測試）、`plugins/lick_stage/contact_regions.py` + `head_direction.py` + `ext_body_zones/regions.py`（幾何運算，共約 25+ 個函式）。
- **具副作用(IO)最集中的模組**：`logutils/csv_logger.py`、`communication/nodered_client.py`、`plugins/*/publisher.py` 與 `output.py`（純 IO，無邏輯可抽離）。
- **依賴 GPU 的函式**：全部集中在 `models/stgcn_model.py` 的 `nn.Module.forward()` 系列與 `CatBehaviorSTGCN`、`detectors/keypoint_detector.py::detect()`、`detectors/behavior_classifier.py::classify()`，以及間接依賴這些的 `frame_processor.py`/`streaming.py`/`routes.py::_build_frame_processor()`。
- **依賴 Flask 的函式**：全部集中在 `server/routes.py`（`register_routes()` 內所有 route）與 `server/flask_app.py::create_app()`；`main.py::run_server_mode()` 間接依賴。
- **依賴 Node-RED 的函式**：`communication/nodered_client.py` 全部、`plugins/lick_stage/publisher.py`、`plugins/*/ext_body_zones/output.py::ZoneHttpPublisher/ZoneMqttPublisher`、`frame_processor.py::_build_nodered_payload()`（組 payload）、`main.py::send_ip_to_nodered()`。

1. **`processors/skeleton_quality_assessment.py::evaluate_window()`（含其 4 個內部純函式）**——校準風險最高（門檻僅用少量影片校準過），目前零測試覆蓋，且是「GCN 分類為主、幾何判斷為輔」覆蓋機制的核心，一旦邏輯跑掉會直接誤判使用者看到的行為標籤。
   > ✅ 執行結果：`processors/tests/test_skeleton_quality_assessment_unit.py`，35 個測試。
2. **`models/stgcn_model.py` 前處理管線 9 個函式**——訓練/推論共用，文件明確要求「順序不可更動」，是全系統正確性的地基，且已知有一支診斷腳本（`test_bone_length_stability.py`）在肉眼校準，代表這裡的行為本來就需要被明確釘住。
   > ✅ 執行結果：`processors/tests/test_stgcn_preprocessing_unit.py`，29 個測試（`interpolate_missing`/`flip_normalize`/`orientation_normalize`/`normalize_skeleton_coords`/`add_velocity_feature`/`compute_bone_feature`/`build_feature_tensor`）。
3. **`config.py::RunModeConfig.is_within_active_window()`**——4 種排程情境邏輯較複雜，docstring 已寫好完整規則，非常適合直接照 docstring 寫成表格驅動測試。
   > ✅ 執行結果：`paper/tests/test_config_unit.py`，81 個測試（含 `RunModeConfig` 與所有環境變數解析函式）。過程中發現 docstring 字面描述與實際「每日固定 06:00–24:00、跨午夜自動暫停」行為有出入，經確認後**維持程式行為不變**，測試按實際（確認過的期望）行為撰寫，未修改 `config.py`。
4. **`server/routes.py::_daily_record_from_dict()`**——docstring 本身提到過「日期格式混用」的歷史 bug，屬於「已知曾經出過包」的解析邏輯。
   > ✅ 執行結果：`server/tests/test_routes_pure_functions_unit.py`，10 個測試（含 `_dataclass_to_jsonable()`）。
5. **`trackers/behavior_tracker.py::_settle_current_behavior()` 與 `.get_alerts()`**——狀態變化清楚、無時鐘依賴，適合建構已知狀態後斷言。
   > ✅ 執行結果：`trackers/tests/test_behavior_tracker_pure_functions_unit.py`，22 個測試（含 `map_gcn_to_tracker()`）。
6. **`utils/helpers.py::get_behavior_name()`**——邏輯簡單但有 3 條規則交錯，值得用表格驅動測試把邊界情況都蓋掉。
   > ✅ 執行結果：`utils/tests/test_helpers_unit.py`，39 個測試（含 `is_stream_url()`、`resolve_video_source()` 非 YouTube 段落）。
7. **`plugins/lick_stage/contact_regions.py` / `head_direction.py` / `ext_body_zones/regions.py` 的幾何函式**——純數學、無外部依賴，適合用已知座標手算期望值驗證。
   > ✅ 執行結果：`plugins/tests/`，共 121 個測試，分 4 個檔案：`test_contact_regions_unit.py`（38）、`test_head_direction_unit.py`（34）、`test_ear_distance_unit.py`（7）、`test_ext_body_zones_regions_unit.py`（42）。過程中發現這些檔案雖然本身零 cv2 邏輯，但透過 `plugins/lick_stage/__init__.py` 的 import chain 間接需要 cv2 才能載入，測試檔都加了 `pytest.importorskip("cv2", ...)` 保護。

### Q7：最適合建立 Regression Test 的模組（依優先順序）

1. **`processors/skeleton_quality_assessment.py`**——用少數幾支已知「正常」與「異常」骨架的影片/JSON 序列，把 `evaluate_window()` 的輸出（`reliable`, `failed_checks`）當快照釘住，未來調整門檻時能立刻看出行為變化範圍。
   > ↪ 實際執行時改以 Unit Test 形式涵蓋（見上方 Q6 第 1 項）：這支模組全部函式都是純函式，能直接手算期望值斷言正確性，比起只能斷言「沒有變化」的快照更有保障，故優先採用 Unit Test。
2. **`models/stgcn_model.py` 完整前處理鏈**——用一組固定的關鍵點序列（可以是合成資料）跑過 `interpolate_missing → flip_normalize → orientation_normalize → normalize_skeleton_coords → build_feature_tensor`，把輸出張量存成快照，任何未來對這條管線的修改都能立刻比對有沒有跑掉。
   > ↪ 同上，實際以 Unit Test 涵蓋（見上方 Q6 第 2 項），理由相同：這條前處理鏈全部是確定性 numpy 運算，能手算期望值。
3. **`processors/frame_processor.py::FrameProcessor.process()`**——目前完全沒有測試、又是最大最複雜的編排函式（先前程式碼品質改善時，就是因為它零測試覆蓋才判斷不適合拆分）。建議先用合成的關鍵點序列走過幾種情境（有貓/無貓/低信心/SQA 覆蓋觸發），把回傳的 `(frame, behavior_id, confidence, class_probs, is_still, activity_value)` 存成快照，之後才有安全網可以真的把這支函式拆開。
   > ✅ 執行結果：`processors/tests/test_frame_processor_characterization.py`（2 個測試，固定 walk 影片）+ `processors/tests/test_golden_dataset.py`（25 個測試，5 種行為 × prediction/statistics/Node-RED payload/CSV/行為區段）。快照存於 `processors/tests/snapshots/`。
4. **`server/routes.py::api_deviation`**——雖然底層 `compute_baseline`/`compute_deviation`/`compute_fusion` 已經有單元測試，但這條路由本身的 JSON 解析、錯誤處理、`InsufficientDataError` 分支目前完全沒有測試覆蓋，適合用 Flask test client 做端對端的整合/回歸測試。
   > ✅ 執行結果：擴大成完整的 **API Regression Test**（`server/tests/test_routes_api_regression.py`，36 個測試），涵蓋 `/api/deviation` 以外的全部 6 個路由（`/`、`/stream`、`/snapshot`、`/video_clip`、`/api/behavior_history`、`/api/overlay`），只驗證 HTTP 狀態碼/JSON schema/錯誤處理，不驗證演算法本身。
5. **`trackers/behavior_tracker.py`**——`save_state()`/`load_state()` 的 JSON 序列化格式若不小心改動，會讓正式環境「重啟後恢復當日資料」這個功能悄悄壞掉，適合對存讀格式做回歸測試。
   > ✅ 執行結果：`trackers/tests/test_behavior_tracker_regression.py`，9 個測試（含 `save_state()`/`load_state()` 存讀格式、跨日重置情境）。

## 執行結果總覽

全部項目已按上述優先順序完成，過程分三階段：

1. **Phase 1（Characterization / Regression Test）**：3 個模組，共 36 個測試。
2. **Phase 2（Unit Test，依 Pure Function 優先順序）**：7 個優先序項目，共 337 個測試。
3. **API Regression Test**：1 個檔案，共 36 個測試。

加上原本就有的 `analytics/tests`（19 個），**全專案共 428 個測試**（`yolo_new` 環境全數可跑；base 環境可跑 170 個，其餘因 cv2/torch/flask 依賴而 skip）。完整清單、操作指令、環境需求見 [0_測試操作手冊.md](0_測試操作手冊.md)。

整個建置過程**沒有修改任何正式程式碼**；唯一一次「疑似需要改程式碼」的狀況（`RunModeConfig.is_within_active_window()` 的 docstring 描述與實際行為有出入）依規定停下確認，確認後判定程式行為本身是對的，只調整了測試的期望值撰寫方式，`config.py` 維持原樣。
