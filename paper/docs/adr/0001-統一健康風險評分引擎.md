# 統一健康風險評分引擎，停用貓咪主控.json 的舊版健康引擎與重複 Discord 警示

**狀態**：accepted（2026-08-08）→ **部分撤銷（2026-08-09 續2）**，見文末「決定撤銷」一節

## 背景

Python 端同時 POST 到 `/yolo_result`（v1，`貓咪主控.json` 接收）與 `/yolo_result_v2`（v2，`cat_health_v3_flow.json` 接收），導致兩個 Node-RED flow **各自獨立**跑一整套健康風險評分：`貓咪主控.json` 用舊版 dScore/fScore/rScore/tScore（30/35/20/15%），`cat_health_v3_flow.json` 用 Class A/B/C 證據融合（45/25/30%，見 `analytics/fusion.py`）。兩者對同一天資料可能算出不同風險等級，且**兩邊 Discord webhook 指向同一頻道**，使用者實際收過對同一狀況判斷不一致的重複通知（2026-08-08 確認）。

## 決定

以 `cat_health_v3_flow.json`（Class A/B/C 融合引擎）作為唯一權威的健康風險評分來源。停用 `貓咪主控.json` 內的「健康引擎分析」「發送提醒→送到 Discord」節點，以及與 `cat_health_v3_flow.json` P1/P2/P5 重複的舊版面板（即時狀態卡片、詳細統計、健康警示、活動力儀表）。

**保留** `貓咪主控.json` 的「儲存CSV」（寫入 `C:\a\noda_data.csv`，`GPT 健康報告.json` 的 GPT 健康報告功能直接依賴此檔案，`cat_health_v3_flow.json` 沒有寫這個檔案）與「影像串流」即時攝影機面板（`cat_health_v3_flow.json` 沒有等效功能）。

## 後果

- 若未來要完全汰除 `貓咪主控.json`，需先把 `noda_data.csv` 輸出與即時影像串流遷移到 `cat_health_v3_flow.json` 或獨立 flow。

## 決定撤銷（2026-08-09 續2）

- 使用者確認**兩個儀表板都會看**（`貓咪主控.json` 自己的 tab 與 `cat_health_v3_flow.json` 的 P1–P4），要求把上一輪切斷的接線**全部復原**，不採用本 ADR §決定 對「即時狀態卡片」「詳細統計」「活動力儀表」「健康引擎分析／健康警示／發送提醒」的停用方案。本 ADR §決定 對 `貓咪主控.json` 面板／引擎部分**視為撤銷**；§背景 描述的重複/不一致 Discord 通知問題**目前依然存在、尚未解決**，是使用者知情後接受的現況，非本次任務範圍。
- 已復原並重新排序「數據分發器」（id `524a127640fe5d6c`）7 個輸出：1 即時狀態卡片 → 2 行為時間紀錄 → 3 詳細統計 → 4 活動力儀表 → 5 健康引擎分析（健康警示／發送提醒） → 6 建立CSV → 7 事件時間軸引擎。對應調整了節點內 `func` 的 `return [...]` 陣列順序（原本第 4 個 output 是活動力儀表的 `{payload: activity_score}`、第 5 個是健康引擎分析的完整 `msg`，順序已對調），確保 return 陣列與 wires 陣列位置一致。
- 同時整理了本 tab 全部 28 個節點的版面座標（依資料流深度分欄、數據分發器的分支依上述新順序由上到下排列），並放大 group 外框（`x:340,y:20,w:1320,h:760`）以容納新版面。JSON 語法已驗證通過。
- **`儲存CSV`／`noda_data.csv`／影像串流／`cat_health_v3_flow.json`／`analytics_deviation_bridge.json` 不受影響**（無跨檔案 `link` 節點耦合）。
- **本 ADR §決定 的「儲存CSV／影像串流保留」部分依然有效**，唯一被撤銷的是「停用健康引擎與重複面板」這部分；若未來要重新處理重複 Discord 通知問題，需要另立決定（例如：讓兩邊引擎算出一致的分數但只由一邊發通知，而非現在的「各自算、各自發」）。
