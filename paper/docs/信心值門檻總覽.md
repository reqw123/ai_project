## ⭐ 核心重點

- ⭐ **① bbox 偵測門檻**：`model.predict(conf=)`，低於門檻整個偵測框丟掉。權威值 `YOLOConfig.CONFIDENCE_THRESHOLD = 0.5`。
- ⭐ **② keypoint 過濾門檻**：17 維逐點 mask，用於 motion_score / 繪圖 / 幾何檢查 / 抖動統計。權威值 `AnomalyDetectionConfig.KP_CONF_THRES = 0.5`。
- ⭐ **③ interpolate_missing 缺失判定**：判「這個關節這一幀算不算缺測」，低於門檻的點用時間軸線性插值補回，再餵進 ST-GCN。內建預設 **0.1**（不是 0.5）。
- ⭐ ③ 用 0.1 是**刻意的**：這一步要保留弱訊號讓時間插值有東西可接；太嚴格會把太多關節判缺測、補出失真軌跡。「要不要採信座標」那種判斷才用嚴格的 0.5。
- 🚨 ③ 的**呼叫點 threshold 值不一致**：即時系統與訓練用 `0.1`，但幾支離線推論工具用 `0.0`——這是已知 train/serve 落差，改動前要三邊一起評估（見下方第 3 節）。

## 1. 三種門檻對照表

| | ① bbox 偵測 | ② keypoint 過濾 | ③ interpolate_missing 缺失判定 |
|---|---|---|---|
| **形狀** | 每個偵測框 1 個純量 | 每幀 17 個關鍵點各 1 個 | 同 ②（17 維），但用途不同 |
| **作用** | 傳給 `model.predict(conf=)`；低於門檻整個框丟掉（等於「這幀沒偵測到貓」） | 逐點布林 mask；低於門檻的點不納入 motion_score / 不畫 / 不參與幾何檢查與統計 | 逐點判「這一幀這個關節算不算缺測」；低於門檻的幀用「該關節其餘可信幀」做時間軸線性插值補回 |
| **典型值** | 0.5 | 0.5 | **0.1**（預設）／0.0（部分工具）／0.5（部分視覺化工具） |
| **權威來源** | `config.py` `YOLOConfig.CONFIDENCE_THRESHOLD` | `config.py` `AnomalyDetectionConfig.KP_CONF_THRES` | `models/stgcn_model.py` `interpolate_missing(threshold=0.1)` |
| **可由設定視窗 / env 調整** | ✅ `yolo.confidence_threshold` / `CAT_MONITORING_YOLO_CONFIDENCE_THRESHOLD` | ✅ `anomaly_detection.kp_conf_thres` / `CAT_MONITORING_KP_CONF_THRES` | ❌ 演算法內部參數，不在設定系統 |
| **命名前綴** | `BBOX_` / `bbox_conf_thres` / 回傳值 `bbox_conf` | `KPT_` / `kpt_conf`（值）／`<用途>_KPT_CONF_THRESHOLD`（門檻） | 參數就叫 `threshold` |

> [!IMPORTANT]
> ①② 是同一次 YOLO-Pose 推論的兩個輸出（`KeypointDetector.detect()` 回傳 `bbox_conf` 與 `kpt_conf`），③ 是拿到 `kpt_conf` 之後、餵進 ST-GCN 之前的一個前處理步驟。三者是管線上**先後不同的三個關卡**，不是同一個東西的三種寫法。

<a id="2-interpolate_missing-的-threshold--原理"></a>
## 2. `interpolate_missing()` 的 `threshold` — 原理

> 📖 **一句話摘要**：`threshold` 決定「conf 多低才算這個關節這一幀是缺測、要用鄰近幀插值補上」。預設 0.1，刻意比偵測/繪圖用的 0.5 寬鬆。

**位置**：`cat_monitoring_system/models/stgcn_model.py`

```python
def interpolate_missing(sequence, conf, threshold=0.1):
    """sequence: (T, V, 2), conf: (T, V) — 時間軸插值補全低信心關節點。

    threshold=0.1 保留弱訊號供時間插值；動作分數過濾使用更嚴格的
    AnomalyDetectionConfig.KP_CONF_THRES=0.5。
    """
    seq = sequence.copy()
    for v in range(seq.shape[1]):
        valid = conf[:, v] > threshold          # 這一關節哪些幀「可信」
        idx = np.arange(seq.shape[0])
        if not np.any(valid):
            seq[:, v, :] = 0                     # 整條時間軸都不可信 → 歸零
        else:
            seq[:, v, 0] = np.interp(idx, idx[valid], seq[valid, v, 0])   # 用可信幀線性內插補其餘
            seq[:, v, 1] = np.interp(idx, idx[valid], seq[valid, v, 1])
    return seq
```

### 🧠 為什麼預設 0.1 而不是 0.5

- 這一步的目的是**在餵進 ST-GCN 前，把時間序列補成連續的**——只要一個關節在窗口內有「夠多可信幀」，中間少數低信心幀就靠內插撐過去，模型才不會吃到跳動或歸零的輸入。
- 用 0.5 會太多關節被判缺測。極端情況是某關節整個窗口都低於 0.5 → 整條歸零 → ST-GCN 該通道輸入全 0 → 分類退化。
- 「要不要相信這個座標值本身」（motion_score、繪圖、SQA 幾何檢查）才用嚴格的 0.5（`KP_CONF_THRES`）。**兩種判斷本質不同，門檻本來就該不一樣。**

### `threshold=0.0` 的意思

`conf > 0.0` → 只有 conf **剛好是 0** 的點才被當缺測。等於「幾乎不靠信心 gate，只補真的沒有座標的點」。

## 3. 🚨 呼叫點 `threshold` 不一致（train / serve 落差）

> [!WARNING]
> 即時推論與訓練用 `0.1`，但幾支「應該重現推論行為」的離線工具用 `0.0`。這是**已知未定案的 train/serve 落差**，改動前必須三邊（訓練 / 即時推論 / 評估）一起評估。

| 呼叫點 | `threshold` | 備註 |
|---|---|---|
| `processors/frame_processor.py:485`（**即時系統**） | `0.1`（預設，未帶參數） | ST-GCN 推論前處理，正式管線 |
| `tools/0_train_gcn.py:498`（**訓練**） | `0.1`（預設，未帶參數） | 切窗前對整段影片補值 |
| `processors/skeleton_quality_assessment.py:106` | `0.1` | SQA 幾何檢查前的補值 |
| `tools/eval_gcn_compare.py` / `eval_ema_ablation.py` / `eval_model_worst_videos.py` | `0.1` | 評估腳本 |
| `tools/1_visualize_three_normalizations.py:1496` | `0.1`（預設） | 三種正規化視覺化 |
| **`tools/1_run_video_inference.py:1578`** | **`0.0`** | 檔內註解：「0.1 會在貓關節信心普遍偏低時把整骨架清零 → 模型輸入全 0 → softmax 均等；改 0.0 只補座標真的是 0 的點」 |
| **`tools/1_classify_and_sort_videos.py:159`** | **`0.0`** | 同上理由 |
| **`tools/2_run_dual_model_compare.py:617`** | **`0.0`** | 同上理由 |
| `tools/test_bone_length_stability.py:614` | `0.0` | `seq_raw`（給幾何檢查用的正規化前像素座標） |
| `tools/1_skeleton_visualizer.py:91` | `VELOCITY_KPT_CONF_THRESHOLD`（2026-08-31 起 = `0.5`） | 速度 overlay 前的補值，視覺化用 |
| `tools/1_export_keypoint_timeseries.py:111` | `INTERPOLATE_KPT_CONF_THRESHOLD`（2026-08-31 起 = `0.5`） | 關鍵點時序匯出，分析用 |
| `tools/1_visualize_interpolation.py:330` | `INTERP_KPT_CONF_THRESHOLD`（2026-08-31 起 = `0.5`） | 插值前後對照視覺化 |

> [!CAUTION]
> `1_run_video_inference.py` 的註解主張 `0.0` 才對，但**訓練（`0_train_gcn.py`）跟即時推論（`frame_processor.py`）用的都是 `0.1`**。也就是說：
> - 若 `0.0` 是對的 → 訓練與即時系統要一起改成 `0.0`。
> - 若 `0.1` 是對的 → 那三支離線工具（`1_run_video_inference` / `1_classify_and_sort_videos` / `2_run_dual_model_compare`）產出的分類結果跟即時系統會有系統性偏差。
>
> 目前**未定案**，維持現狀。要動的話請開一個獨立議題，把訓練 → 推論 → 離線評估三邊一起對齊。

## 5. 命名慣例（來自 2026-08-31 重構）

| 概念 | 值變數 | 門檻常數 |
|---|---|---|
| ① bbox 偵測 | `bbox_conf` | `BBOX_CONF_THRESHOLD` / `bbox_conf_thres` |
| ② per-keypoint | `kpt_conf`（17 維） | `<用途>_KPT_CONF_THRESHOLD`（`DRAW_` / `JITTER_` / `VELOCITY_` / `BONE_` / `EAR_` …） |

| 行為分類 | — | `STGCN_BEHAVIOR_LABEL_CONFIDENCE_THRESHOLD` |

> [!TIP]
> **規則**：任何跟 YOLO 有關的門檻都必須帶 `BBOX_` 或 `KPT_` 前綴。看到裸 `conf_thres` / `CONF_THRESHOLD` 就是漏網之魚，應補前綴。

> 常見陷阱（已修）：`KeypointDetector` 的建構子參數過去叫 `conf_thres`，實際是 **bbox** 門檻（類別名叫 *Keypoint*Detector 更容易誤會），現已改為 `bbox_conf_thres`。

<a id="6-cheat-sheet"></a>
## 6. Cheat Sheet

```text
要調「偵測不到貓 / 誤檢背景」   → ① YOLOConfig.CONFIDENCE_THRESHOLD（設定視窗 or CAT_MONITORING_YOLO_CONFIDENCE_THRESHOLD）
要調「靜止判定 / 骨架該不該畫」 → ② AnomalyDetectionConfig.KP_CONF_THRES（設定視窗 or CAT_MONITORING_KP_CONF_THRES）
要調「ST-GCN 輸入補值鬆緊」     → ③ interpolate_missing(threshold=) —— 不在設定系統，要改程式碼，且訓練/推論/評估要一起改
lick_stage 插件的門檻           → plugins/lick_stage/config.py（不吃主 config.py）
ext_body_zones 的門檻           → plugins/lick_stage/ext_body_zones/config.py
tools 腳本各自的門檻            → 各腳本開頭「信心值門檻設定」區塊，全部 *_KPT_CONF_THRESHOLD / YOLO_CONF_THRESHOLD
```
