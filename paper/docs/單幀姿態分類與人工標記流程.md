> [!IMPORTANT]
> **⭐ 核心發現**
>
> 1. **tag 是整支影片一起貼的**：舔毛／抓癢影片裡躺著休息的幀也叫 lick／scratch。只用 tag 訓練，模型會學到
>    「躺著＝lick」；對 tag 自己的吻合度很高（0.94）是假象，要用人工考卷才看得出來。
> 2. **骨架的逐段標記能糾正 tag**：骨架影片裡停下來的片段標成 stop，剛好是 tag 缺的「躺著但不是 lick」。
> 3. **單幀看不到動作**：甩頭單幀像坐著、stop 裡站著不動的幀跟 walk 一樣 → 類別要依「姿勢」定義才分得開。
> 4. 模型判成 other 的 tag 圖，使用者看過 110 張**全部**是躺／坐 → 模型可以拿來找 tag 錯誤。

## ❌ 踩過的坑

| 坑 | 正確做法 |
|---|---|
| 用資料集檔名當標籤或驗證 | ❌ 檔名是來源影片名，**不代表行為**（使用者明確要求）；只拿來判斷「是不是同一支影片」做分組 |
| 用 tag 吻合度當模型好壞 | ❌ tag 有系統性錯誤，一律看人工考卷 |
| 考卷跟訓練資料的類別定義不一致 | ⚠ 三類→四類時，考卷裡依「行為」標的 walk 有躺著的貓，要依姿勢重看 |
| 長檔名（>260 字元）讀寫失敗 | 這台 `LongPathsEnabled=0`；Python 路徑前面加 `\\?\`（工具已處理） |
| bash heredoc 裡寫 `"\\\\?\\"` | ❌ 反斜線會被吃掉；含長路徑前綴的腳本用檔案寫好再執行 |
| `report_dir()` 以為會建資料夾 | ❌ 只回傳路徑，寫檔前要 `mkdir(parents=True, exist_ok=True)` |
| Roboflow MCP 匯出版本、列 batch、刪圖 | ❌ OAuth 權限被擋；網頁的 Filter by Tag 要付費 |
| 按 tag 抓圖 | ✅ MCP `images_search`（`tag=`，每頁上限 250）拿 id／檔名／split，對本機匯出檔；重名時下載原圖 `source.roboflow.com/9tHmXeHc17ON83IsNUSM7uEGnAY2/<id>/original.jpg`（免登入），letterbox 成 640 後比對 |
| `flip_idx: [0..16]` | ❌ 沒交換左右；用 `Downloads\data.yaml` |
| 以為依檔名分組就不會外洩 | ❌ 骨架影片改過檔名（`lick_42.mp4`），Roboflow 圖是原檔名（`lick42_mp4-0008`），分組對不起來；要比畫面（訓練腳本的同源比對，會自動執行） |
| 同源比對時遮掉貓只比背景 | ❌ 純白背景變異量≈0 會爆掉，同源／不同源分數反而更重疊；整張圖比＋低門檻寧可多判 |
| yolo_new 載入 model.joblib：`No module named '_loss'` | model 是 base 的 sklearn 1.7.2 存的，yolo_new 是 1.9.0 讀不了；`1_classify_new_images_by_pose.py` 偵測在 yolo_new、分類自動換 base |
| 拿考卷圖測試分類工具得到 0.944 | ❌ 最終模型訓練時看過這些圖（213 張在 tag 裡）與同影片，只能證明流程能跑，不是準確度 |
| 直接跑工具出現 `UnicodeEncodeError: 'cp950'` | 終端機是 cp950，印 ▶ 會掛；前面加 `PYTHONUTF8=1`（失敗時會留下空的報告資料夾，要刪） |
