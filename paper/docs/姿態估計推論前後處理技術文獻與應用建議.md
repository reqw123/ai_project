## 一、整體管線分兩段：推論前 vs. 推論後

搜尋結果一致把姿態估計管線切成：影像輸入 → **前處理**（resize/normalize/batching）→ 模型推論 → **後處理**（NMS、信心值過濾、時序平滑、插值補缺）→ 輸出。近期模型（YOLO26-pose、DETRPose 等）的趨勢是把部分後處理內化進模型本身（NMS-free 推論），但對本專案這種「偵測 + 獨立時序分類器」的兩階段架構來說，後處理仍然是關鍵環節。[Best Pose Estimation Models](https://blog.roboflow.com/best-pose-estimation-models/) ｜ [YOLO26 Pose Estimation Tutorial](https://learnopencv.com/yolo26-pose-estimation-tutorial/)

## 三、本次掃描最值得跟進的發現：One Euro Filter

這是搜尋過程中冒出來、專案目前完全沒有的技術，而且**直接對應到 Kalman 實驗踩過的坑**：

> "Production systems apply a temporal filter — typically a One-Euro filter or a Kalman filter — to each keypoint independently. **The One-Euro filter is the default because it tracks fast motion without lag while suppressing low-amplitude jitter.**"
> —— [Noise Filtering Using 1€ Filter](https://jaantollander.com/post/noise-filtering-using-one-euro-filter/) ｜ [OneEuro Filter 概覽](https://mohamedalirashad.github.io/FreeFaceMoCap/2021-12-25-filters-for-stability/)

**為什麼這個發現重要**：`memory/project_kalman_smoothing_eval.md` 記錄的三輪 Kalman 實驗裡，一個反覆出現的診斷是——shake（快速動作）需要的平滑強度跟 stop（幾乎靜止）差很多，用同一組全域 Q/R 參數是妥協，而且不管訓練期匹配與否，較強平滑都會系統性拖累 shake。**One Euro Filter 的設計目標正好是解決這個問題**：它的平滑係數是「自適應」的，速度快時自動減少平滑（低延遲跟上快動作），速度慢時自動加強平滑（壓掉靜止時的抖動）——不需要像 Kalman 那樣為 shake 和 stop 挑同一組妥協參數。

**具體技術細節**：兩個超參數 `minCutoff`（降低會減少低速抖動）跟 `beta`（增加會減少高速延遲），比 Kalman 的 process/measurement noise 更直觀，調參空間也更小。

**跟本專案的落地方式**：架構上可以直接比照現有 `SMOOTHING_KIND` 的 dispatch 設計（`none`/`ema`/`kalman`）新增 `oneeuro` 選項，複用已經建好的整套驗證基礎設施（`eval_accuracy_smoothing_compare.py` 的 `SMOOTHING_CONFIGS`、`tools/0_train_gcn.py` 的 `smoothing_kind` 訓練期分派、`eval_gcn_compare.py` 的 `--smoothing_kinds` 匹配評估），複用成本很低——不用重新設計實驗流程，只要新寫一個 `keypoint_oneeuro.py`（結構可以參考現有 `models/keypoint_kalman.py`）。

## 四、對本專案的具體應用建議（依優先度排序）

**高優先（低成本、直接可測，建議下次投入）**

1. **實作 One Euro Filter 並照 Kalman 同一套流程驗證**（推論期套用 → 若有訊號再重訓匹配評估）。這是本次掃描最具體、成本最低、理論上最對症下藥的方向。

**中優先（值得盤點，成本可能不高）**

2. **確認 `test_bone_length_stability.py` 是否已在 `frame_processor.py` 實際生效**，如果只是離線診斷測試，補一個推論期的骨骼長度修正步驟（median bone length + 門檻修正）成本不高，且是文獻裡動物姿態估計常見的做法。
3. **補一個 MAD-based 時序離群值修正**，跟現有 `skeleton_quality_assessment.py`（幾何合理性）互補，用途類似 Kalman 協方差判斷「這個預測有多不可信」，但更輕量、不用整套濾波器狀態機。

**低優先（成本高或跟既有決定衝突，暫緩）**

4. **SmoothNet 式學習型精修網路**——概念上是路線 B（T-LEAP 端到端時序模型）的近親，使用者已經決定 T-LEAP 不採納（見 memory `project_kalman_smoothing_eval`），這條大概率也會被同樣的理由暫緩，除非之後有新證據支持重啟時序模型投資。
5. **OKS-based Pose-NMS**——只有支援多貓場景才用得到，目前系統只做單一貓咪偵測，非急迫。
6. **推論前影像品質過濾（模糊/曝光偵測）**——本次搜尋沒查到足夠具體的做法，不建議現在投入，需要之後另外查證才有動手的依據。
