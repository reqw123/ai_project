# ⚙️ 設定視窗（settings_window.py）欄位對照表

> [!NOTE]
> **本文件的用途**
>
> 列出 `settings_window.py` 目前管理的全部 **68 個欄位**，依 11 個分頁分類，
> 對照它們的 JSON 路徑（`runtime_settings.current.json`）、環境變數名稱、`config.py`
> 對應的 class attribute，以及儲存前的驗證規則。
>
> 內容直接由 `settings_manager.py` 的 `FIELD_SCHEMA`（唯一事實來源）產生，
> 若欄位有異動，`FIELD_SCHEMA` 才是準；本文件如果過期，以程式碼為準。

---

## 📖 一句話摘要

設定優先順序固定是 **環境變數 > `runtime_settings.current.json` > `config.py` 內建預設值**；
本文件表列的每一列，都是可以在設定視窗裡看到、編輯、存進 JSON 的欄位。

---

## 🚫 完全排除（不在設定視窗、不進 JSON、不可覆寫）

| 項目 | 原因 |
|---|---|
| `STGCNTrainingConfig`（整個 class） | 唯一權威來源是 `stgcn_config.yaml`，設定視窗不可修改 |
| `STGCNConfig.SEQUENCE_LENGTH` | 訓練 checkpoint 架構相容性參數，改了會跟 checkpoint 對不上 |
| `STGCNConfig.FEATURE_MODE` | 同上，須與訓練時一致，否則輸入通道數不符 |
| `STGCNConfig.NUM_CLASSES` | 同上，模型輸出類別數固定為 5，非執行期可調參數 |
| `SystemInfo`（整個 class） | 純識別常數（系統名稱／版本／輸出尺寸），非操作性設定，本來就沒有 env 覆寫 |
| `BehaviorTrackingConfig.BEHAVIOR_CATEGORIES` | id → 行為名稱對照表，綁定模型輸出索引，非可調參數 |

> 💡 `STGCNConfig` 底下的 `WINDOW_STRIDE`／`TARGET_MODEL_FPS`／`ENABLE_FPS_DOWNSAMPLE`／`KP_EMA_ALPHA`
> 是「推論期」參數，**有**收進設定視窗（見下方「ST-GCN 推論」分頁）——跟上面排除的
> 「訓練架構相容性」參數是不同性質，不要混淆。

### 進階設定

> 💡 以下三個端點預設由「Flask 與 Node-RED」分頁的 Node-RED 主機／Port 推導而成
> （`http://{host}:{port}/...`），這裡開放個別覆寫成完全不同的網址，一般情況不需要碰。
>
> 2026-08-26 修正：這 3 個欄位一旦存過一次 `runtime_settings.current.json`（幾乎必然，
> `_on_save()` 每次都整包寫回全部欄位），`config.py` 的 `_runtime_default()` 就會一路
> 優先讀 JSON 裡的字面值，換 Host/Port 後這 3 個端點不會自動跟著換，會停留在存檔當下
> 的舊值。已在 `settings_window.py` 補上 `_wire_nodered_endpoint_autosync()`：只要某個
> 端點欄位目前的值還維持著「上一次 Host/Port 組出來的樣式」（沒被使用者手動改成別的
> 網址），改 Host 或 Port 時就會自動跟著同步；一旦偵測到使用者已經手動覆寫過某個端點
> （值不符合自動推導樣式），就不再自動覆蓋那一個，尊重刻意的個別覆寫。

## 🧠 補充說明

- **優先順序**：環境變數 > `runtime_settings.current.json` > `config.py` 內建預設值。設定視窗存檔只會寫
  `runtime_settings.current.json`；某欄位若對應環境變數已設定，視窗會標示「[環境變數]」並提醒存檔不會立即生效。
- **驗證規則欄的「輸出路徑」**：檢查父目錄存在（通過）／不存在但可建立（警告，不擋存檔）／
  不存在且無寫入權限（錯誤，擋存檔）。
- **必要檔案**（`required_file`，目前只有 `YOLO_MODEL`／`STGCN_MODEL`）：存檔前若檔案不存在會直接擋下。
- **選填檔案**（`optional_file_warn`）：缺漏只警告，不阻擋存檔，可留空。
