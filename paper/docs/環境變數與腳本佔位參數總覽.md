# 🌐 環境變數與獨立腳本佔位參數總覽

> [!NOTE]
> **本文件的用途**
>
> 列出 `paper/` 底下**目前所有可用的環境變數**，以及 `cat_monitoring_system/tools/` 底下
> 27 支獨立腳本裡「沒有環境變數包裝、必須直接開檔案改原始碼」的**佔位參數**——
> 兩者是互補的兩種調整機制：環境變數可以在不改程式碼的情況下臨時覆寫；佔位參數
> 則是這些獨立工具腳本一貫的用法（先打開改檔案開頭寫死的常數，再執行）。
>
> `config.py` 底下由 GUI（`settings_window.py`）管理的 68 個欄位，已經有專門的
> [`設定視窗欄位對照表.md`](設定視窗欄位對照表.md) 完整列出（JSON 路徑／環境變數／
> 驗證規則），本文件**不重複列出那 68 個**，只補上它管不到的部分。如有異動，以
> 程式碼為準。

### 1.2 config.py：刻意排除在 GUI 之外、但仍讀環境變數的欄位

這幾個屬於「訓練架構相容性參數」或「訓練設定唯一權威來源」，改了會跟已訓練好的

仍然有效：

| 環境變數 | 對應位置 | 說明 |

| `CAT_MONITORING_STGCN_FEATURE_MODE` | `STGCNConfig.FEATURE_MODE` | 特徵模式；`main.py` 主流程用，跟 [1.5 節](#sec-1-5)（已移除）的 `STGCN_FEATURE_MODE` 是不同機制 |

> [!NOTE]
> **`STGCN_FEATURE_MODE` 已移除（原本 4 支腳本共用：`1_classify_and_sort_videos.py`／
> `1_run_video_inference.py`／`1_visualize_three_normalizations.py`／
> `2_run_dual_model_compare.py`）。**
>
> 這 4 支腳本都有各自一段「讀 checkpoint 的 `bn_input.weight` 通道數，跟目前
> feature_mode 不符就自動改用對的模式」的邏輯，這段邏輯永遠會蓋掉手動設定的值——
> 也就是說只要 checkpoint 讀得到，這個環境變數在正常情況下**根本不會被用到**。
> 唯一還有作用的情境是 checkpoint 讀取失敗時的 fallback 值，屬於邊緣情況，
> 已改成直接寫死 `STGCN_FEATURE_MODE = "xy"`，不再讀環境變數，功能上沒有損失。
> 不建議併進 `stgcn_config.yaml` 集中管理——那份 YAML 只代表「最近一次訓練」的
> 設定，`2_run_dual_model_compare.py` 需要同時比較兩個可能不同 feature mode 的
> checkpoint，一份共用設定檔無法同時代表兩個答案；checkpoint 自身的權重形狀才是
> 唯一不會過期的真相來源。

<a id="sec-pixabay-warning"></a>
> [!WARNING]
> **`1_自動抓取.py` 第 65 行目前的寫法會讓環境變數失效，而且硬編碼了一組看起來是真實的
> API key：**
> ```python
> PIXABAY_API_KEY = "53629479-5c0…" or os.environ.get("PIXABAY_API_KEY", "")
> ```
> Python 的 `or` 只要左邊字串非空就直接短路——硬編碼字串已經非空，所以
> `os.environ.get(...)` 那段**永遠不會被執行**，設定 `PIXABAY_API_KEY` 環境變數也不會有
> 任何效果。`PEXELS_API_KEY` 那行（第 66 行）硬編碼是空字串，短路條件不成立，所以那個
> 環境變數目前實際是有效的，兩行行為不一致。
>
> 這組硬編碼金鑰本身也是一個獨立問題：如果 `1_自動抓取.py` 有進版本控制，這組 key
> 就已經留在 git 歷史裡了。要不要我另外幫你評估要不要移除硬編碼、改成純讀環境變數，
> 並確認要不要去 Pixabay 後台輪替這組 key？（這是文件之外的另一個修改，不在這次「寫
> 說明文件」的範圍內，先在這裡提醒你。）
