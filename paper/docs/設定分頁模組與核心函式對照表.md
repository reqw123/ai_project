# 🧩 設定視窗（settings_window.py）分頁 × 模組/核心函式對照表

> [!NOTE]
> **本文件的用途**
>
> `settings_window.py` 右欄「說明文件」面板顯示的內容來源。跟舊版
> `設定視窗欄位對照表.md`（逐欄位對照 JSON 路徑／環境變數／`config.py` 屬性）
> 不同，這份文件回答的是另一個問題：**這個分頁調的參數，實際上是被
> `cat_monitoring_system/` 底下哪個模組、哪個函式讀走、用掉的？**
>
> 每一列列出「模組檔案」「核心函式／類別」「這個函式做什麼」，內容是實際讀過
> 原始碼（grep 該分頁對應的 `config.py` class 名稱在哪裡被 import/使用）驗證過
> 的結果，不是憑檔名猜測。程式碼異動導致行為改變時，本文件可能過期——以程式碼
> 為準，發現對不上請回報或直接修正本文件。

---

## 📖 一句話摘要

大部分分頁的參數不是被「單一函式」讀取，而是在系統啟動組裝階段（
`server/routes.py` 的 `_build_frame_processor()`）被讀進來、組裝成物件，之後
在每一幀的處理管線裡才真正發揮作用。這條管線的核心只有一個進入點：

> `cat_monitoring_system/processors/frame_processor.py` 的
> `FrameProcessor.process(self, frame)` —— 依序呼叫關鍵點偵測、身份驗證、
> ST-GCN 分類、異常偵測、骨架品質評估、行為追蹤、視覺化疊圖、CSV 記錄，是
> 幾乎所有分頁的參數最終匯集發揮作用的地方。下面各分頁只列出「這個分頁的參數
> 主要影響管線裡的哪一段」，不是每個分頁都重複列一次 `process()` 本身。

---

## 📋 各分頁對照表

### 模型與輸入來源

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/server/routes.py` | `_build_frame_processor()` | 讀取 `ModelPaths`（YOLO/ST-GCN 模型檔路徑、影像來源、輸出目錄）組裝出 `FrameProcessor` 實例，是這幾個路徑設定實際生效的唯一組裝點；`main.py` 本身不直接碰 `ModelPaths`。 |
| `cat_monitoring_system/processors/frame_processor.py` | `FrameProcessor.__init__()` | 接收 YOLO/ST-GCN 模型路徑、影像來源等參數，載入模型與影像來源（`cv2.VideoCapture` 或攝影機索引）。 |

### YOLO 推論

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/detectors/keypoint_detector.py` | `KeypointDetector.detect()` | 對單一影格跑 YOLO-Pose 推論，回傳關鍵點座標／信心值／bbox／bbox 信心；沒偵測到貓時四項全回傳 `None`。 |
| `cat_monitoring_system/server/routes.py` | `_build_frame_processor()` | 讀取 `YOLOConfig.IMAGE_SIZE`／`CONFIDENCE_THRESHOLD` 傳入 `FrameProcessor`，決定推論解析度與偵測信心門檻。 |

### ST-GCN 推論

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/detectors/behavior_classifier.py` | `BehaviorClassifier.classify()` | 用一段時間窗的關鍵點時序座標跑 ST-GCN 分類，回傳行為 id、信心值、各類別機率。 |
| `cat_monitoring_system/models/stgcn_model.py` | `interpolate_missing() / build_feature_tensor()` | 推論前處理：低信心關鍵點時序插值、把多個通道組合成模型輸入張量（順序見「ST-GCN 前處理順序」，不可更動）。 |
| `cat_monitoring_system/processors/frame_processor.py` | `STGCNConfig.WINDOW_STRIDE / KP_EMA_ALPHA` | 這兩個屬性在這裡被讀取使用：控制 ST-GCN 推論的滑動步長，以及關鍵點 EMA 平滑係數。 |

### 執行模式與排程

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/main.py` | `run_server_mode() / run_gui_mode()` | 依 `RunModeConfig.MODE`（`"server"`／`"gui"`）決定啟動 Flask 伺服器模式，還是本地端直接顯示視窗的 GUI 模式。 |
| `cat_monitoring_system/main.py` | `_scheduler_loop()` | 週期性檢查 `RunModeConfig.is_within_active_window()`，依排程時間範圍自動啟動/暫停處理管線。 |
| `cat_monitoring_system/server/routes.py` | `_ensure_processor_started() / _pause_processing()` | 首次請求時視目前是否在排程允許時間內決定要不要啟動處理管線；離開允許時間時暫停讀幀/推論，但不釋放已載入的模型與影像來源。 |

### Flask 與 Node-RED

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/server/flask_app.py` | `create_app()` | 建立 Flask app、註冊路由；依 `BaselineDashboardConfig.ENABLED` 決定要不要一併掛載 baseline dashboard 的藍圖。 |
| `cat_monitoring_system/communication/nodered_client.py` | `NodeRedClient.send_data()` | 把資料丟進背景佇列後立即回傳，實際傳送是非同步進行，不會卡住呼叫端。 |
| `cat_monitoring_system/main.py` | `send_ip_to_nodered()` | 程式啟動時對 Node-RED 送一次上線通知，附上目前主機 IP。 |
| `cat_monitoring_system/dashboard/refresher.py` | `start_background_refresh() / compute_and_cache_once()` | Baseline dashboard 背景週期性重新計算並快取結果，避免每次請求都重算。 |

### 視覺化與串流顯示

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/processors/visualizer.py` | `Visualizer.draw()` | 把偵測/分類結果（骨架、bbox、行為文字、機率條）疊圖到當前畫面上。 |
| `cat_monitoring_system/server/streaming.py` | `SharedFrameStreamer` | 單一寫入執行緒統一做幀處理與 JPEG 編碼，多個 `/stream` 客戶端共用同一份已編碼影格，避免每個連線各自重複編碼。 |

### 異常偵測與骨架品質

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/processors/anomaly_detector.py` | `AnomalyDetector.detect()` | 輸入當前幀的關鍵點與信心值，回傳是否靜止不動、以及量化的活動力數值。 |
| `cat_monitoring_system/processors/skeleton_quality_assessment.py` | `evaluate_window()` | 骨架品質評估的唯一對外進入點，用骨長穩定度／軀幹角度抖動等指標，判定該時間窗的 ST-GCN 分類結果是否可信。 |
| `cat_monitoring_system/processors/frame_processor.py` | `SQAConfig.ENABLE_SQA_DUAL_JUDGMENT` | 總開關，這個屬性決定要不要呼叫 `evaluate_window()` 做雙重判定（ST-GCN 分類結果 + 骨架品質，兩者都通過才採信）。 |

### 行為追蹤與警報門檻

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/trackers/behavior_tracker.py` | `ImprovedBehaviorTracker.update()` | 用本幀的行為 id 與活動力數值更新累積統計、行為轉移矩陣、活動視窗，是行為追蹤狀態機的核心更新函式。 |
| `cat_monitoring_system/utils/helpers.py` | `get_behavior_name()` | 依 `BehaviorTrackingConfig.STGCN_BEHAVIOR_LABEL_CONFIDENCE_THRESHOLD` 信心門檻，決定回傳實際行為名稱、還是「低信心」提示文字，供 visualizer 等呼叫端共用。 |
| `cat_monitoring_system/processors/visualizer.py` | `get_behavior_name()` | 疊圖時呼叫這個函式：信心低於門檻的行為標籤，顯示成低信心提示文字而不是直接顯示類別名稱。 |

### 貓咪身份驗證

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/detectors/identity_verifier.py` | `IdentityVerifier.verify()` | 用顏色直方圖比對，判定畫面中偵測到的 bbox 是不是登記過的目標貓，回傳是否為目標貓、比對到的身份鍵值、距離值；比對結果不確定時保守回傳「不是目標貓」。 |
| `cat_monitoring_system/processors/frame_processor.py` | `FrameProcessor.process() → IdentityVerifier.verify()` | 過濾掉非目標貓的偵測結果——多貓環境下，畫面中其他貓的偵測結果會被直接忽略，不會進入後續 ST-GCN 分類。 |

### 日誌、CSV、資料庫與輸出路徑

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/logutils/csv_logger.py` | `CSVLogger.log()` | 寫入一列逐幀紀錄並立即 flush，確保程式異常中斷時已寫入的資料不會遺失。 |
| `cat_monitoring_system/logutils/csv_logger.py` | `BehaviorSegmentLogger.log_segment()` | 寫入一筆「已結束的行為段落」紀錄（開始/結束時間、持續秒數等）並立即 flush。 |
| `cat_monitoring_system/analytics/daily_store.py` | `save_day() / load_history()` | 把每日彙整資料 upsert 進 SQLite（同一天重複寫入會覆蓋，不會重複累積）；讀出歷史紀錄供 baseline／dashboard 計算使用。 |

### 進階設定

> 這個分頁目前只收 `NodeRedConfig` 底下三個端點 URL 欄位
> （`ENDPOINT_NOTIFY`／`ENDPOINT_RESULT`／`ENDPOINT_RESULT_V2`），不是
> `NodeRedConfig` 整個 class。

| 模組檔案 | 核心函式／類別 | 說明 |
|---|---|---|
| `cat_monitoring_system/communication/nodered_client.py` | `NodeRedClient / _EndpointWorker` | 每個結果端點各自對應一個背景 worker 執行緒與佇列，非同步把推論結果送往指定端點 URL，任一端點卡住不會拖累其他端點。 |
| `cat_monitoring_system/main.py` | `send_ip_to_nodered()` | 啟動時 POST 到 `ENDPOINT_NOTIFY` 通知上線，附上本機 IP。 |
